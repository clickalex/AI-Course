Agent red-teaming playbook

Chatbots answer; agents ACT — browse, spend, email, delete. Learn to threat-model the full attack surface, run structured adversarial campaigns, and build the sandbox + forensics that catch what testing misses.

2. Campaign playbook (2-week sprint)

  1. Scope + rules: which agent, which env (staging clone with fake data), what’s off-limits, stop conditions. Written authorisation. Always.
  2. Attack matrix: surfaces × goals (exfil, fraud, sabotage, persistence) → 30–60 concrete scenarios with success criteria.
  3. Execute + log everything: full traces (prompts, tool calls, approvals) — the trace IS the deliverable, not just the finding.
  4. Score: breach rate per surface, time-to-breach, detection rate (did monitors fire?), blast radius of worst breach.
  5. Fix + re-test: patch controls, re-run failed scenarios + regressions. Unfixed critical = no launch.

3. Sandbox + forensics (for what testing misses)

  • Sandbox: agents run with network allowlists, fake-data staging twins, rate-limited tools, and kill switches. Production credentials never in agent reach.
  • Trace forensics: immutable log of every step (input hashes, tool args, approvals, outputs) — reconstruct any incident minute-by-minute.
  • Drift alarms: new tool combinations, new destinations, approval-rate spikes, off-hours spend — page a human, pause the agent.
  • Incident runbook: freeze agent → preserve traces → assess blast radius → rotate credentials → notify → post-mortem → add the scenario to the suite.

Red-team ethics

Scope in writing, staging data only, no real-customer impact, no persistent backdoors “for later testing”, disclose to vendors before publishing. The goal is a safer agent, not a trophy screenshot.

Short notes

P2. Red-team finds the agent emails internal docs to any address in a ticket. Full response?

Critical: block launch. Fix: egress allowlist (known domains only) + PII/doc-classifier on attachments + human approval for external sends + per-ticket address verification. Re-test the scenario + 5 variants, add to CI suite, audit past sends for exploitation, post-mortem on why egress review was missing.

P3. Design drift alarms for a finance-ops agent. 4 signals + response each.

(1) New payee + first-time amount spike → pause + human approve. (2) Tool sequence never seen in training → sandbox replay, alert. (3) Approval-bypass attempts / prompt-injection patterns → freeze + security review. (4) Off-hours or velocity anomalies → step-down to read-only + notify owner. All with trace links and one-click kill.
