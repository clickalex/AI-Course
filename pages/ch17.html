Chapter 17 · Classical AI · UG

Search, games & classical AI

Before learning from data, AI was search: try actions, keep the promising paths. This is still how planners, games, and many agents work.

Figure 17.1 — States as nodes, actions as edges, goal as a star.

An agent in the Russell & Norvig sense has PEAS: Performance measure, Environment, Actuators, Sensors. Uninformed search ignores a guess of remaining cost; informed search uses a heuristic h(n).

AlgorithmIdeaComplete / optimal?

Games

Minimax assumes an optimal opponent. Alpha-beta prunes branches that cannot affect the decision. Evaluation functions + iterative deepening + transposition tables made chess engines; AlphaGo mixed search with learned nets.

Task environments at a glance

PropertyQuestion it asksContrast pair
ObservableCan the agent see the full state?Chess board (fully) vs driving in fog (partial)
DeterministicDo actions have one fixed outcome?Chess rules vs weather/traffic (stochastic)
EpisodicDoes this decision bind future ones?Sorting a parcel vs playing a chess move
Static / dynamicDoes the world change while thinking?Crossword puzzle vs the road while you plan
Discrete / continuousFinite actions or real-valued control?Board moves vs steering angle and torque
Agent countAre other minds pursuing goals?Sorting numbers vs tennis, pricing, ad auctions

The PEAS table and these six axes decide the algorithm: partial observability implies belief tracking; stochastic, multi-agent worlds push toward expectimax, MDPs (Ch 15) or learned policies instead of exhaustive search.

Worked example — choosing a search algorithm

Unit-cost maze: BFS gives the shortest path with the least code. Weighted road map: UCS (Dijkstra), or A* with straight-line distance as h. Huge branching factor + a good heuristic: IDA* or hierarchical A*. Two-player zero-sum game: minimax + alpha-beta with a heuristic/learned evaluation; when the simulator is cheap and outcomes are random, Monte Carlo tree search (the engine of AlphaGo). Notice the theme: use knowledge (the heuristic) to buy search you cannot afford exhaustively.

Short notes

Classical AI = formulate as a graph, search it. Heuristics encode domain knowledge. Combinatorial explosion is why we later learned functions instead of enumerating worlds — but search is back inside agents (tool loops, tree-of-thought, MCTS).

Point notes

  • PEAS describes a task.
  • A* = UCS + heuristic.
  • Admissible h never overestimates.
  • Minimax + α-β for two-player zero-sum.
  • Search ≠ learning, but they combine.

MCQs

5 questions · scored

1. A* is optimal when h is:

If h overestimates, A* can skip the true best path.

2. Alpha-beta pruning:

Same answer as minimax, fewer nodes.

3. BFS is optimal when:

Shallowest = cheapest only for uniform step cost.

4. In the PEAS description of a self-driving car, the actuators are best exemplified by:

Sensors perceive; actuators change the world — steering, braking and throttle actuate.

5. Which uninformed search typically uses the least memory?

DFS stores a stack of depth O(d); BFS/UCS store a frontier of O(branching^depth).

P1. Straight-line distance to the goal is a common h. Why is it admissible for road maps?

No road can be shorter than the Euclidean straight line (in flat geometry). So h never overestimates true remaining driving distance. Hence A* with this h is optimal.

P2. When would greedy best-first search be chosen over A* in practice, and what is given up?

Greedy ranks nodes by heuristic h alone, ignoring travelled cost g. With a very good heuristic it can reach a goal while expanding far fewer nodes and less frontier memory — useful for non-critical game NPCs or approximate routing — but it is neither optimal nor complete (it can dive into a dead-end). Use it when a fast, good-enough path matters and you can replan; use A* when the cheapest path is required.

Self-mark:

P3. State minimax in one sentence and explain what alpha-beta pruning changes.

Minimax chooses the move whose worst-case outcome against an optimally playing opponent is best: the maximizer maximises, the minimizer minimises, recursively. Alpha-beta keeps bounds α (best guaranteed for max) and β (best guaranteed for min) and prunes any branch that cannot change the root decision, returning the identical move while examining fewer nodes — especially with good move ordering.
