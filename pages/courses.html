MCQs — checkpoints after the courses

15 questions

1. [Course 1] In Python 3, input() always returns:

Convert with int(input()) or float(input()) when you need a number.

2. [Course 1] langs = ["py", "js"]; what does langs.append("sql") do?

Lists are ordered and mutable; append adds one item at the end.

3. [Course 1] To run a saved script main.py from the terminal (Level 4 skill), you type:

The Python interpreter runs the file; this is how real programs start.

4. [Course 1] You write the same 5 lines in three places. The Pythonic fix is:

Functions are the unit of reuse — one job, one name, called anywhere (Ch 30 §4).

5. [Course 1] In OOP, a class is best described as:

The class defines data + behaviour; each object is one concrete instance.

6. [Course 2] In a housing table used to predict price, the price column is the:

Features are the inputs; the label is what you want to predict (Ch 6–7).

7. [Course 2] A model scores 99% on its training data but only 60% on new data. This is:

The generalization gap is the tell: great on seen data, weak on unseen data (Ch 7).

8. [Course 2] You have no labels and want to group customers by similarity. You need:

No labels → unsupervised; grouping by similarity is clustering (Ch 9).

9. [Course 2] At its core, an LLM generates text by:

Next-token prediction over a context window — which also explains knowledge cutoff and non-determinism (Ch 12–14).

10. [Course 2] A chatbot states a wrong fact confidently and invents a fake citation. This is:

A core GenAI limitation — verify claims and ground the model (RAG, Ch 42/48).

11. [Course 3] In retrieval-augmented generation (RAG), the vector store is used to:

Embed chunks → store → similarity-search the question → feed top chunks to the LLM (Ch 42 §2).

12. [Course 3] A well-engineered prompt mostly needs:

Clarity + context + constraints, refined through iteration — the course’s core prompting lesson (Ch 42 §1).

13. [Course 3] An embedding is:

Meaning → vectors: this is what makes semantic search and RAG possible (Ch 6, Ch 14).

14. [Course 3] You need an app that answers strictly from your company handbook. The best design is:

RAG gives grounding, easy updates and references — exactly the chatbot the course builds (Ch 42/48).

15. [Course 3] Agentic AI differs from a plain chatbot because agents:

An LLM-driven supervisor orchestrating tools, memory and knowledge (Ch 23–24) — guardrails still required.

P2. [Course 1] Write a script average.py that reads scores.txt (one number per line) and prints the average, rounded to 2 decimals. Run it from the terminal.

def read_scores(path):
    with open(path) as f:
        return [float(line) for line in f if line.strip()]

def main():
    scores = read_scores("scores.txt")
    if not scores:
        print("no scores")
        return
    print(f"average = {sum(scores)/len(scores):.2f}")

if __name__ == "__main__":
    main()

Run: python average.py. This combines Level 2 (functions), Level 3 (comprehension-style loops), Level 4 (files, module, terminal) — and mirrors Ch 30 §4–6.

P3. [Course 2] A team wants to predict monthly rent from a labeled table of 10,000 listings (area, bedrooms, neighbourhood, rent). Name the paradigm, say whether the target is continuous or categorical, and describe what over-fitting would look like here plus one way to catch it.

Paradigm: supervised learning, specifically regression (rent is a continuous number, not a category). Over-fitting: the model exploits quirks of these 10,000 rows (e.g., a specific landlord’s naming style) and predicts well on them but poorly on new listings. Catch it with a hold-out set (or cross-validation): train on one split, evaluate on data the model never saw — a big train/test gap is the warning sign (Ch 7).

Self-mark:

P4. [Course 2] Draft a prompt that asks an LLM to summarize a 10-page report for a busy CEO. Then list three limitations from the course that could affect the output, and one mitigation for each.

Example prompt: “Summarize the attached 10-page report in 5 bullet points for a CEO: lead with decisions needed, keep numbers exact, no new facts.”

Limitations: (1) Prompt sensitivity — vague prompts give vague summaries; mitigate with explicit instructions (audience, length, focus) as above. (2) Hallucination — the model may add plausible-but-wrong “facts”; mitigate with “no new facts” instructions and spot-checking bullets against the source. (3) Knowledge cutoff / context limits — anything not in the prompt or report is unknown to the model; mitigate by pasting the relevant report text (or using retrieval, Ch 42/48).

Self-mark:

P5. [Course 3] Rewrite this weak prompt into a strong one, and explain what you changed: “Tell me about our product.” Context: you sell noise-cancelling headphones online.

Strong version: “You are a support agent for an online store selling noise-cancelling headphones. In 5 friendly bullet points for a first-time buyer, explain: how active noise cancelling works, what battery life to expect, and how to choose the right model. Do not invent specifications.”

Changes: (1) a role/persona, (2) a named audience, (3) an explicit task + format + length, (4) constraints (“do not invent specs” — an anti-hallucination guard), and (5) the output is testable, so you can iterate — the prompt-engineering loop from the course and Ch 42 §1.

Self-mark:

P6. [Course 3] Design (don’t build) a mini RAG chatbot for your college’s course handbook: list the pipeline steps, the tools you would pick, and two checks that prove the answers are trustworthy.

Pipeline: collect handbook PDFs → chunk the text (~300–500 tokens, with overlap) → embed the chunks (e.g., text-embedding-3-small) → store in a vector store → on each question: embed the question, retrieve the top-k similar chunks, prompt the LLM with “answer only from the given context, cite the page” → Streamlit UI. Tools: Python + LangChain + OpenAI API + Streamlit — the same stack as the course’s chatbot section.

Trust checks: (1) Grounding/citation check — every claim must map to a retrieved chunk; (2) refusal test — questions outside the handbook should get “I don’t know”, never an invented answer (evals: Ch 42 §3).
