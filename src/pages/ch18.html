Logic, knowledge & planning

Symbolic AI stores facts and rules, then infers. Brittle at scale — still unmatched when you need guarantees.

Figure 18.1 — Planning is search over states described by formal logic.

Knowledge representation

  • Propositional logic — symbols true/false; SAT solvers; resolution.
  • First-order logic (FOL) — objects, predicates, quantifiers ∀ ∃.
  • Expert systems — if–then rules + inference engine (MYCIN). Knowledge-acquisition bottleneck.
  • Ontologies / knowledge graphs — typed entities and relations (next in Ch 20).
  • Fuzzy logic — degrees of truth; still used in control.

Planning

STRIPS/PDDL: states as predicates, actions with preconditions and effects. Search in state space (or plan space). Hierarchical task networks (HTN) and modern LLM agents both decompose goals — one with formal operators, one with text.

CSP

Variables, domains, constraints. Backtracking + forward checking + heuristics (MRV). Map colouring, scheduling, Sudoku.

Neuro-symbolic

Nets propose; logic checks. Example: an LLM writes a SQL query; the database schema is the constraint system. PhD topic: differentiable theorem proving, NS-CL, Scallop.

English → first-order logic cheat sheet

English sentenceFOL
All humans are mortal∀x Human(x) → Mortal(x)
Some students like maths∃x Student(x) ∧ Likes(x, maths)
No robot sleeps∀x Robot(x) → ¬Sleeps(x)
Every employee has exactly one manager∀x Employee(x) → ∃!y Manages(y, x)

Exam trap: pair ∀ with implication and ∃ with conjunction. “Some students like maths” as ∃x Student(x) → Likes(x,maths) is vacuously true in a world with no students (anything implies anything for non-students).

Why SAT/SMT solvers quietly run industry

Chip verification, route scheduling, rostering and configuration validation compile constraints into SAT/SMT instances; modern CDCL solvers handle millions of clauses and give unsatisfiable cores that explain failures. When an LLM generates a config or query, a solver or schema checker verifying feasibility is neuro-symbolic engineering — language proposes, logic disposes.

Short notes

Logic gives sound conclusions from written knowledge. Planning is search with structured actions. CSPs are the practical core of scheduling. Combine with learning when knowledge is incomplete.

Point notes

  • KB + inference = expert system.
  • FOL > propositional in expressivity, harder computationally.
  • STRIPS action = pre / add / delete.
  • CSP: assign without violating constraints.

P1. When would you still pick a rule engine over an LLM for loan eligibility?

When regulators require explainable, auditable, deterministic decisions (age ≥ 18, DTI cap). Encode those as rules; maybe use ML only for a risk score that a human or rule can override. Don’t let a stochastic token model be the law.

P2. Write “every student owns some laptop” in first-order logic and explain why propositional logic handles it poorly.

∀x Student(x) → ∃y (Laptop(y) ∧ Owns(x, y)). Propositional logic only has fixed true/false symbols, so it would need a separate ground proposition for every (student, laptop) pair and cannot express “for every” or “there exists” over an open, growing domain — the number of formulas explodes and new individuals need new axioms.

P3. Define a STRIPS action Go(a, r₁, r₂): give its precondition and add/delete effects. What problem does this style solve?

Precondition: At(a, r₁) ∧ Connected(r₁, r₂). Delete: At(a, r₁). Add: At(a, r₂). Only changed fluents are listed, which sidesteps the frame problem (everything not in add/delete stays true, without writing axioms for each). A planner chains such operators to turn the initial-state predicates into the goal predicates.
