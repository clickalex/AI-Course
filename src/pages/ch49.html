3. How reasoners are trained (RLVR in one paragraph)

Take verifiable tasks (math with answers, code with tests, proofs with checkers). Let the model roll out long chains, reward only correct final outcomes (RL on verifiable rewards), and thinking strategies emerge: backtracking, self-checking, trying alternatives. Then distil the reasoning traces into smaller models. Lesson: verification is the scarce resource — invest in checkers, tests, and judges.

4. When to pay for thinking

  • Worth it: math, code, planning, multi-hop analysis, anything with a checker. Route hard queries to reasoners automatically (Ch 50 cascade).
  • Not worth it: chitchat, simple extraction, latency-critical UX. A reasoner “thinking” 2 minutes about a greeting is a bug — set budgets per route.
  • Always: keep reasoning traces for debugging, but show users the verified answer — long internal monologues aren’t explanations (faithfulness gap).

Reasoning pitfalls

Overthinking simple queries (cost + latency) · unfaithful chains (confident steps, wrong answer — verify outcomes, not prose) · reward hacking the verifier (optimising the judge, not the truth) · no budget caps on agentic loops.

Short notes

Ladder: CoT → self-consistency → tree search → verifiers → tool-checked. Accuracy scales with thinking budget (diminishing). RLVR trains reasoners on verifiable outcomes; distil traces down. Route by difficulty, budget per route, verify outcomes — chains are evidence, not proof.

Point notes

  • Think longer > grow bigger (often).
  • Vote, search, verify, execute.
  • RLVR: reward correct outcomes.
  • Budget thinking per route.
  • Verify answers, not prose.

Practice questions

P1. Design the reasoning strategy for a math-tutor bot (accuracy + cost + UX).

Route: easy → fast model + CoT; hard → reasoner with self-consistency (N=5) + symbolic/code checker; verify final answer before showing. Stream a short “working” state, reveal clean solution steps (regenerated, not raw traces). Budget: cap tokens/query; cache common problems. Eval: accuracy on a held-out problem set + student ratings.

P2. Your verifier-rewarded model games the judge (long, flattering, wrong). Fix it.

Classic reward hacking of a learned judge. Fixes: ground rewards in verifiable outcomes (tests, execution, hidden answers); ensemble judges + human spot audits; penalise length; adversarial eval slice targeting sycophancy; hold out a judge the policy never sees for honest measurement.

P3. When is tree-of-thought worth it over self-consistency?

When intermediate states are verifiable and mistakes compound: puzzles (Game of 24), planning, multi-step code. ToT’s branch-score-prune explores alternatives where single chains derail. Cost is high, so gate it: try CoT/self-consistency first, escalate only on verifier failure.
